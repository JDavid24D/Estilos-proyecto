Tecnologías

En resumen, el sistema se construirá con:

  • Lenguaje y framework: Python y Django.
  • Base de datos: PostgreSQL.
  • Procesamiento de Excel: openpyxl y pandas.
  • Interfaz web: HTML, CSS, JavaScript, Bootstrap, Chart.js y FullCalendar.
  • Herramientas: Git y GitHub, Figma, Enterprise Architect, pruebas de Django y Lighthouse.
  • Publicación (por definir): HTTPS, Docker, Gunicorn y Nginx.

Lenguaje y framework

Python
Qué es: lenguaje de programación. Se lee fácil y tiene muchas librerías para trabajar con datos y archivos.
Para qué la usamos: es el lenguaje de todo el sistema por dentro: leer los Excel, calcular horas trabajadas, atrasos y ausentismos, y armar los reportes (RF11 a RF18).
Django
Qué es: framework web de Python. Ya trae inicio de sesión, usuarios y permisos, formularios, plantillas y un panel de administración.
Para qué la usamos: usuarios y roles (RF01 a RF03). Los permisos se revisan en el servidor (RNF03) y las contraseñas se guardan con hash y sal (RNF01). También sirve para que parámetros como la tolerancia de atrasos y el día de corte se cambien sin tocar el código (RF13). La bitácora de auditoría (RNF05) la hacemos como un modelo propio.

Base de datos

PostgreSQL
Qué es: sistema de bases de datos relacional, gratuito y de código abierto. Django trabaja con él directamente.
Para qué la usamos: guarda colaboradores, marcaciones originales, horarios, permisos, horas extra, usuarios, bitácora e historial de cargas. Sus restricciones de unicidad evitan marcaciones duplicadas (RF07) y las marcaciones se guardan tal como llegan (RNF18). Los respaldos diarios se hacen con sus propias herramientas (RNF17).

Procesamiento de Excel

openpyxl
Qué es: librería de Python para leer y escribir archivos .xlsx.
Para qué la usamos: leer los archivos de ZKTeco identificando las columnas por su nombre y no por su posición (RNF14), y generar los reportes en Excel (RF24).
pandas
Qué es: librería de Python para trabajar con tablas de datos.
Para qué la usamos: ordenar y sumar las marcaciones por colaborador y por día, y calcular los totales de los reportes. Ayuda a procesar un archivo de unas 60 000 marcaciones en menos de 2 minutos (RNF12).

Interfaz web

HTML, CSS y JavaScript
Qué es: los tres lenguajes base de cualquier página web: estructura, estilo y comportamiento.
Para qué la usamos: las pantallas del sistema, armadas con las plantillas de Django.
Bootstrap
Qué es: librería de estilos para páginas que se adaptan al tamaño de la pantalla.
Para qué la usamos: que la aplicación se vea bien desde 1366 × 768 y en tablet (RNF13), con tablas y formularios ordenados. También para aplicar los colores corporativos de NETTPLUS cuando los entregue (RNF08).
Chart.js
Qué es: librería de JavaScript para hacer gráficos.
Para qué la usamos: los gráficos del dashboard (horas, atrasos, ausentismos). Cada gráfico va con su tabla de datos para no depender solo del color (RNF10).
FullCalendar
Qué es: librería de JavaScript para mostrar calendarios.
Para qué la usamos: el calendario de turnos fijos y rotativos de cada colaborador (RF10).
Chrome, Edge y Firefox
Qué es: los navegadores con los que se abre la aplicación.
Para qué la usamos: probamos en las dos últimas versiones estables de cada uno (RNF13).

Herramientas de desarrollo, diseño y pruebas

Git y GitHub
Qué es: Git es un sistema de control de versiones. GitHub guarda el repositorio en la nube.
Para qué la usamos: trabajar los tres sobre el mismo código sin pisarnos y guardar el historial de cambios.
Figma
Qué es: herramienta para diseñar pantallas de una aplicación.
Para qué la usamos: hacer el prototipo del dashboard para que NETTPLUS lo apruebe antes de programar.
Enterprise Architect
Qué es: herramienta para hacer diagramas de modelado como los UML.
Para qué la usamos: los diagramas del proyecto, como el diagrama de contexto que pide la plantilla de visión y alcance.
Pruebas de Django
Qué es: sistema de pruebas automáticas que viene incluido en Django.
Para qué la usamos: comprobar que los cálculos de horas, atrasos y ausentismos dan lo mismo que un cálculo manual en Excel (objetivos OB-02 y OB-04).
Lighthouse
Qué es: herramienta de Chrome que revisa accesibilidad y rendimiento de una página.
Para qué la usamos: revisar el contraste de los textos y el uso con teclado (RNF09).

Seguridad y publicación (por definir)

Estas dependen de dónde se aloje la aplicación, que todavía no sabemos. Lo que sigue es lo que usaríamos en principio:

HTTPS (TLS 1.2 o superior)
Qué es: conexión cifrada entre el navegador y el servidor.
Para qué la usamos: toda la comunicación del sistema va cifrada (RNF02).
Docker
Qué es: herramienta que empaqueta la aplicación con todo lo que necesita para que funcione igual en cualquier servidor.
Para qué la usamos: instalar la aplicación y la base de datos en el servidor de NETTPLUS o en la nube.
Gunicorn y Nginx
Qué es: Gunicorn ejecuta la aplicación Django y Nginx recibe las visitas y las dirige a ella.
Para qué la usamos: publicar la aplicación en un servidor, con la disponibilidad que se acuerde (RNF16).

Tecnología para más adelante: API de ZKTeco

Si NETTPLUS habilita la API de ZKTeco, usaríamos la librería requests de Python para pedir los datos y una tarea programada (por ejemplo cron) para hacerlo todos los días. Para probar la conexión sirve Postman. Como la carga de datos está separada del cálculo (RNF15), cambiar de Excel a API no modifica las reglas de cálculo. Esto queda fuera de la primera versión.
